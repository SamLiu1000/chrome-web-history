> - 标签收纳页：`pages/views/stash.js`（686–1389 行，自研指针事件 DnD，注释自称"逆向 onetab 2.21"）

> - 书签管理：`pages/views/bookmarks.js`（672–722 行，原生 HTML5 DnD）

## 一、OneTab 2.21 的拖拽架构（参考基准）

逆向其打包源码后整理的完整管线：

| 组件 | 实现要点 |
|---|---|
| **按下检测器 `_n`** | pointerdown 进入待定；pointermove 只记坐标，rAF 合帧检测；阈值 3px（平方比较）。超过即 `body.dnd-no-select` + 源元素 `pointer-events:none` |
| **合成事件分发** | 关键技巧：源元素 `pointer-events:none` 后浏览器不再派发其下事件的悬停，OneTab 用 `document.elementsFromPoint` 找到指针下元素（跳过源元素子树），**派发合成 `pointermove`/`pointerup`**，投放区因此照常工作 |
| **区域控制器 `Ro.ia()`** | 每个投放区同时监听 `dragover`+`pointermove`、`dragleave`+`pointerleave`、`drop`+`pointerup` 双通道；用 WeakSet "认领"事件，保证只有最内层投放区处理一次 |
| **光标幽灵** | `Kn` 注册表：dragged-group 21×18px、dragged-tab 21×5px、folder 21×18px、multi-dragged-* 等 PNG，`position:absolute` 跟随指针（+20px 偏移）、`cursor:move`、zIndex 100000；**多选标签拖拽时显示首个标签的标题文字** |
| **占位符 `ut`（landingDiv）** | `background: var(--drop-area-gradient)`（明/暗两套 45° 斜纹）、`border: 3px dotted var(--link-color)`、圆角 10px、高度=被拖行高。**参与布局，行实时让位** |
| **几何缓存** | 按（容器、currentTarget、子元素数、scrollTop、key 列表）缓存行中点数组；占位符已在场时从其高度中扣除得自然几何；MutationObserver 监听子列表变化自动失效 |
| **自动滚动** | 参数：边缘 48px、起始 80px/s、最大 640px/s、二次曲线；rAF 循环按 dt（秒）换算；支持 `hover`（指针下容器）/`origin`（拖拽源容器）两种目标模式 |
| **落点语义** | 行区：最近行中点→前/后；组/文件夹元素：大虚线框→落到组尾；标签→文件夹：先建 window 组再整体移入；**组→组=融合**（子项按序并入、源组删除）；左栏树三段：上 20%（≥9px）前 / 下 20% 后 / 中 within，展开文件夹的"后"只在体部底部 2px |
| **校验矩阵 `ks()`** | 锁定标签不能拖进普通组；锁定组不能拖进 window/tabGroup；回收站条目不能进主列表；标签不可与组/文件夹混拖（toast 提示）；不可拖进自身/祖先（toast 提示） |
| **取消/落库** | 取消时按保存的 parent/nextSibling **拓扑序还原 DOM**；落库先即时视觉（单项：占位符直接替换为真实元素），再异步写入 |
| **外部拖入** | 支持 `text/uri-list`、`text/html`、`text/plain`、`text/x-moz-place`，解析成标签插入落点 |
| **其它** | Esc 取消（capture 阶段）且取消后保持禁选到下一次 mouseup；拖拽结束记时间戳，50ms 内的点击被吞；第二根手指按下会优雅结束当前拖拽；全链路 RTL 支持 |

## 二、本程序已经追平甚至超越的点

收纳页 `stash.js` 的逆向成果相当完整，以下均已对齐：

- **双通道启动**：移动 3px 即拖 + 按住不动 250ms 也进拖拽（OneTab 只有 3px 通道）
- **rAF 每帧判定 + 起步几何快照 + `compOf` 占位补偿数学**：等效 OneTab 的几何缓存，且主区判定零 `elementFromPoint`、零强制回流（只有左栏用）
- **指示线参与布局、行实时让位、判定前先隐线再量几何**：无布局反馈振荡（与 OneTab 同思路）
- **组头三段语义**（顶部 20% 插组前 / 收起时底部 20% 插组后 / 中部 within 高亮）、组间新建组、列表末尾新建组
- **拖到左栏**：文件夹/主列表=新建组收纳；组条目=并入；回收站=整组移入
- **多选标签整批拖动**（跨组按视图顺序收集）
- **自动滚动 48px / 80–640px/s 二次曲线**：参数与 OneTab 完全一致，且注释显示已处理 OneTab 同款的 dt 换算问题
- **Esc 取消、松手后 250ms 吞点击、空组自动消除**
- **`memoryMove` 固定区钳制**：不能把非固定标签插到 `pinnedCount` 之前
- **主区直接组间重排**（组头顶部=插到它前面）——OneTab 主区组↔组只能融合，重排必须去左栏树，**这条本程序比 OneTab 多一条交互路径**

## 三、差距清单

### A. 标签收纳页（stash.js）

| # | 差距 | OneTab 的表现 | 本程序现状 | 优先级 |
|---|---|---|---|---|
| A1 | **无光标幽灵** | 拖组/文件夹时有 dragged-group.png 小图标跟随光标；多选标签显示首个标题文字 | 拖动中只有占位线，光标是空的，"抓起来"的感觉弱 | **P0** |
| A2 | **无外部拖入** | 把浏览器里的链接、选中的文字、别的应用里的 URL 拖进收纳页，直接解析成组插入落点 | 完全未实现：全页无 document 级 `dragover`/`drop`，无 `dataTransfer` 解析 | **P0** |
| A3 | 触屏不可用 | `touch-action:none` 开关（默认关）+ pointer 事件体系天然支持 | `.tg-row`/组头未设 `touch-action:none`，触屏按住即触发容器滚动并 `pointercancel`（OneTab 默认也没开，属"都没做好"） | P2 |
| A4 | 锁定语义偏薄 | `ks()` 校验矩阵 + 树区向上遍历祖先锁定 | `locked` 只防整组删除/进回收站；**可以拖进锁定组、锁定组也能被移到别处** | P1（取决于产品意图） |
| A5 | 固定区无视觉边界 | 两边都没有专门的分隔线（pinnedCount 概念两边都有） | 拖拽时用户不知道落到哪里会"掉进"固定区 | P2 |
| A6 | 指示线视觉 | 3px **点线** + 斜纹底 + 圆角 10px，高度=行高−6px | 2px 虚线 + 纯色淡底 + 圆角 8px（`.st-drag-ind`） | P2（抛光） |

### B. 垂直标签栏（sidepanel.js）——差距最大

1. **原生 HTML5 DnD 的先天短板**（OneTab 全部规避，本程序照单全收）：
   - **触屏/触控笔完全不能拖拽排序**（HTML5 DnD 不支持触摸事件）
   - 拖拽幽灵是浏览器自动生成的行截图，**无法定制**（比如显示"N 个标签"计数徽标）
   - **不能多选整批拖动**（收纳页支持，标签栏不支持，手感不一致）
   - 无 Esc 取消、无可调阈值/长按启动
   - 拖拽过程中无法根据悬停目标动态给提示（如"将移动到 窗口 2"）
2. **固定区投放别扭**：拖进/拖出固定区只能靠"拖到某个固定标签上"触发 toggle；**目标窗口没有固定标签时拖不进固定区**（`dropInfo` 只认 `.tab` 行，见 `performMove`）；且固定区与普通区之间**没有分隔线**。
3. **跨窗口拖拽反馈弱**：拖到别的窗口分组，只有行级细线（`drop-above/below`），**不高亮整个目标窗口分区**——Chrome 原生标签栏拖到别的窗口是会高亮整窗的。
4. **过滤态落点待验证**：搜索过滤后 `hide` 的行不参与命中，但 `performMove` 按 `allTabs` 的 index 计算落点，过滤态下"看到的行序"与"落点位置"可能不一致（建议实测）。
5. **体验一致性**：同一扩展内，收纳页是精细自研 DnD，标签栏是原生 DnD，两处手感明显不同。

### C. 书签管理（bookmarks.js）

1. 只有 `drop-into` 高亮目标文件夹、**不能排序**（Chrome 书签管理器本身也不能，但与本程序另两处体验不一致）。
2. 同为原生 DnD，触屏不可用、无幽灵定制、无 Esc。

## 四、改进优先级建议

| 优先级 | 事项 | 工作量 | 说明 |
|---|---|---|---|
| **P0** | 收纳页加光标幽灵 | 小 | 复用 `.st-drag-ind` 思路做一个 `position:fixed` 跟随层：拖组显示小图标（可画 21×18 的 SVG/PNG），多选标签显示"N 个标签"文字；rAF 里更新 left/top 即可 |
| **P0** | 收纳页支持外部拖入 | 中 | document 级 `dragover`/`drop`（preventDefault 才收），按 `text/uri-list`/`text/html`/`text/plain` 分支解析，落点复用现有 `t.gid/t.index`；解析逻辑可参考 OneTab 的 `Xs()` 或本程序已有的"导入文本"链接提取 |
| **P1** | 垂直标签栏换自研指针 DnD | 大 | 直接把收纳页验证过的管线（3px+长按、rAF、占位、自动滚动）搬到标签栏；一次性解决触屏、多选拖动、Esc、窗口高亮、固定区分隔线所有问题 |
| **P1** | 锁定语义对齐 `ks()` | 小 | 补：禁止拖进锁定组、锁定组只能留在原层级的规则（先想清楚产品意图再定） |
| **P2** | 收纳页 `touch-action:none` | 极小 | 一行 CSS；长按 250ms 通道已存在，触屏拖拽即通 |
| **P2** | 指示线视觉统一 | 小 | 点线 + 斜纹底 + 圆角 10px，向 OneTab 靠拢 |
| **P2** | 书签页支持排序 | 中 | 行级 before/after 占位，而不是只能落入文件夹 |
| P2 | 垂直标签栏过滤态落点实测 | 小 | 若不复一致，过滤态隐藏行也参与 index 计算或拖拽中临时清除过滤 |

## 五、结论

收纳页的拖拽已经完成度 90%+，剩下的主要是**"抓起来的质感"**（光标幽灵）和**"从外面拿进来"**（外部拖入）两个 OneTab 标志性能力；垂直标签栏是最大的短板——原生 HTML5 DnD 导致触屏、多选、定制幽灵、Esc 取消全线缺失，且与收纳页手感割裂，建议作为下一阶段主攻方向。
